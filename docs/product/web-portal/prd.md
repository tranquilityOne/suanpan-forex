## 3. 背景与目标

### 3.1 业务背景

- 前台是用户直接看到的部分：财经日历、7×24 快讯、央行利率、交易计算器、交易时段，中英双语。第一阶段不做会员；页面由服务端渲染，配合输出缓存和 CDN 缓存，访问效果接近静态站点。
- 流量主要来自搜索引擎。每个指标一个详情页、每个工具一个页面，是 SEO 的主力页面类型。
- 主要面向中国大陆用户，但第一阶段部署在香港且未备案，百度收录会受限。所以中文站前期的流量预期要放低；英文站以 Google 为主。
- 前台和 data-hub 在同一个解决方案里（data-hub DEC-019），用只读数据库账号直接查询对外视图（data-hub DEC-021）。数据库或采集端出故障时，前台靠输出缓存和 CDN 缓存继续提供已缓存的页面。中期前台迁回大陆后，改连大陆的数据库只读副本（data-hub BR-119）。

### 3.2 产品目标（SMART）

| 目标编号 | 目标描述 | 衡量指标 | 目标值 | 衡量方式 |
|---|---|---|---|---|
| G-001 | 大陆用户访问速度可接受 | 首屏 LCP（大陆 4G 网络） | P75 ≤ 2.5 秒 | 大陆多地拨测 |
| G-002 | 页面被搜索引擎收录 | sitemap 中被 Google 收录的 URL 占比 | 上线 8 周内 ≥ 80% | Google Search Console |
| G-003 | 快讯及时展示 | 快讯发布到前台页面上出现的时延 | P95 ≤ 15 秒 | 前端埋点 |
| G-004 | 流量增长 | 自然搜索 UV | 上线后 4 周确定基线，之后按月设定目标 | 统计工具 |

## 5. 用户场景与故事

### 5.1 核心使用场景

**场景 1：从搜索进入指标详情页**

| 维度 | 描述 |
|---|---|
| 触发条件 | 用户搜索"非农 预期""美国 CPI 公布时间"等 |
| 前置状态 | 指标详情页已被收录 |
| 用户行为 | 进入指标详情页，查看定义、下次公布时间、历史数据，再点进财经日历 |
| 系统响应 | 页面直接显示完整内容（不依赖 JavaScript）；时间按用户时区显示 |
| 预期结果 | 用户获得答案，并继续浏览日历或快讯 |
| 异常分支 | 数据加载失败时显示最近一次的数据和更新时间 |

**场景 2：晚上等数据公布**

| 维度 | 描述 |
|---|---|
| 触发条件 | 美国数据公布前，用户打开快讯页 |
| 前置状态 | 已有预告快讯 |
| 用户行为 | 停留在快讯页 |
| 系统响应 | 新快讯自动出现，不需要刷新页面；带利多利空结论的快讯显示"不构成投资建议" |
| 预期结果 | 用户在官方公布后很短时间内看到结果 |
| 异常分支 | 连续读取失败时，显示"数据更新中断"，恢复后自动消失 |

**场景 3：用仓位计算器算手数**

| 维度 | 描述 |
|---|---|
| 触发条件 | 用户准备下单前 |
| 前置状态 | 无 |
| 用户行为 | 输入账户货币、余额、风险比例、止损点数、货币对 |
| 系统响应 | 在浏览器本地计算并给出手数；需要汇率时使用当天的参考汇率，并显示汇率日期 |
| 预期结果 | 得到可直接使用的手数 |
| 异常分支 | 输入不合法时即时提示 |

### 6.2 功能详情

#### FR-001：双语站点结构

**需求描述**：中英文是两套独立的 URL，内容一一对应，可以互相切换。

| 规则编号 | 规则描述 |
|---|---|
| BR-001 | 中英文使用独立的 URL 前缀（`/zh/`、`/en/`）；同一内容的两种语言页面互相标注 hreflang，根路径作为 x-default |
| BR-002 | 切换语言后，停留在同一内容的对应语言页面 |
| BR-003 | 首次访问根路径时，按浏览器语言选择语言版本；无法判断时默认中文 |
| BR-004 | 机器翻译的内容（新闻）必须显示"机器翻译"标识 |

**验收标准**
1. 每个页面都有另一种语言版本的入口和 hreflang 标注。
2. 切换语言后不丢失当前页面。
3. 浏览器语言为英文时，首次访问进入英文站。

#### FR-002：时区识别与切换

**需求描述**：默认按用户所在时区显示时间，也可以手动切换。

| 规则编号 | 规则描述 |
|---|---|
| BR-005 | 默认使用浏览器时区；用户手动切换后，全站时间（日历、快讯、交易时段）同步更新 |
| BR-006 | 所有时间显示都带时区标识（如 UTC+8） |
| BR-007 | 关闭 JavaScript 时，页面仍以 UTC 显示时间，不出现空白或错误时间 |

**验收标准**
1. 切换时区后，日历、快讯、交易时段的时间同步变化。
2. 在夏令时切换前后，各时区的显示都正确。

#### FR-003：首页（待原型）

**需求描述**：首页集中展示最新快讯、今日日历（高、中重要性）、央行利率摘要和工具入口。

| 规则编号 | 规则描述 |
|---|---|
| BR-008 | 首页的快讯区与快讯页同步自动刷新（FR-016） |

**验收标准**
1. 首页包含最新快讯（≥ 20 条）、今日日历、央行利率摘要、工具入口。
2. 新快讯不需要刷新页面就能出现。

#### FR-004：财经日历页（待原型）

**需求描述**：按日分组展示日历事件，支持视图切换和筛选。展示字段：时间、经济体/货币、重要性、指标名、公布值、预期值、前值（含修正）。

| 规则编号 | 规则描述 |
|---|---|
| BR-009 | 视图：今天 / 明天 / 本周 / 下周；筛选：经济体、重要性；筛选条件体现在 URL 中，可以分享（可深链） |
| BR-010 | 公布值相对预期值的着色规则与 data-hub BR-074 一致（利好本币、利空本币、符合预期三种）；没有预期值或指标无方向时不着色；着色同时配有文字或符号，颜色不能是唯一的信息载体 |
| BR-011 | 时间精度为"仅日期"或"待定"的事件，分别显示"全天"或"待定" |
| BR-012 | "延迟""取消""已更正"状态有明确标识 |
| BR-013 | 预期值标注为"市场预期"；前值被修正时显示修正后的值，并标识"已修正" |
| BR-014 | 点击指标名进入指标详情页（FR-005） |

**验收标准**
1. 可以组合筛选，复制 URL 到新窗口后看到相同的筛选结果。
2. 着色与 data-hub 的快讯结论一致。
3. 没有预期值的事件不着色。

#### FR-005：指标详情页（待原型）

**需求描述**：每个指标一个页面（中英文各一），是 SEO 的主力页面。内容包括：名称、定义说明、发布机构、发布频率、影响方向说明（如"公布值高于预期通常利好美元"）、下次公布时间、最近一次公布结果、历史数据表和走势图。

| 规则编号 | 规则描述 |
|---|---|
| BR-015 | URL 稳定且可读，如 `/zh/indicator/us-nfp` |
| BR-016 | 历史数据标注数值口径（回填 / 首次公布值 / 修订值），与 data-hub BR-065 一致 |
| BR-017 | 指标说明为空时不展示说明区块 |
| BR-018 | data-hub 的历史回填（P1）完成前，历史区只展示上线后累计的公布记录 |

**验收标准**
1. §10.9（data-hub PRD）中的每个指标都有中英文详情页。
2. 关闭 JavaScript 时，页面仍能看到说明和历史数据表。
3. 回填的数据带口径标识。

#### FR-006：快讯页（待原型）

**需求描述**：7×24 快讯按时间倒序展示，可以按类型（数据公布、央行、预告、汇总）和重要性筛选。

#### FR-016：数据刷新与降级

**需求描述**：页面中需要实时更新的区块（快讯流、今日日历等）在浏览器端定时局部刷新；服务端用输出缓存和 CDN 缓存减轻数据库压力，并在数据变化时按 data-hub 的通知让缓存失效；查询失败时降级展示已有数据。

| 规则编号 | 规则描述 |
|---|---|
| BR-046 | 浏览器端局部刷新频率：快讯 ≤ 10 秒、日历 ≤ 60 秒、其他 ≤ 10 分钟；浏览器标签页不可见时降低频率 |
| BR-047 | 局部刷新失败时继续展示已有数据；连续失败 3 次后显示"数据更新中断"，恢复后自动消失 |
| BR-048 | 收到 data-hub 的缓存刷新通知（data-hub FR-023）后，让对应页面的输出缓存和 CDN 缓存失效；缓存最长有效期与 data-hub BR-118 一致 |

**验收标准**
1. 数据库不可用期间，已缓存的页面仍可访问；局部刷新连续失败 3 次后出现提示。
2. 恢复后提示自动消失，新数据正常显示。
